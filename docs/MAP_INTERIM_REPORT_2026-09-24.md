# Mappa 지도 중간 보고서 — 2026-09-24 KST

## 1. 현재 판정

**macOS 오프라인 지도 수직 시안은 실제 데이터로 동작한다. 제품 수준 지도와 iPhone 지도는 아직 완료되지 않았다.** 세계·동아시아·한국·수도권을 서로 다른 상세도의 로컬 PMTiles로 렌더링하고, 이동·확대·라벨·축척·네 가지 색상 시안을 macOS Metal 출력에서 확인했다. 그러나 수도권 상세 원본은 z12까지이며, 도로의 실제 위치 정합성을 기준점별로 정량 검증하지 않았다. iOS 앱에는 지도 렌더러가 연결되지 않았고, 실기기 설치는 Apple Personal Team의 기기 등록 한도에 막혀 있다.

| 영역 | 현재 판정 | 확인 근거 |
|---|---|---|
| Rust 카메라·투영·줌·축척 | 검증됨 | 단위 테스트, z11.4/z16 실제 캡처 |
| 로컬 데이터 읽기·MVT 해독 | 검증됨 | 네 아카이브 1,868개 타일 전수 해독, 오류 0 |
| macOS GPU 지도·도로·라벨 | 검증됨 | Apple M4 Metal 캡처, 이동 벤치마크 |
| 네이버 지도 수준의 도로 위치·완전성 | 미검증 | 기준점별 오차 측정 및 누락 도로 조사가 아직 없음 |

| GitHub 전달 | 미완료 | `origin`은 `seoyd/mappa`, 지도 작업은 현재 로컬 미커밋 상태 |

이 판정에서 “검증됨”은 지정한 macOS 환경에서 실행해 확인했다는 뜻이며, iPhone이나 전국 지도 품질을 뜻하지 않는다.

## 2. 구현 방향과 데이터 출처

지도 코드는 Rust로 구성했다. `mappa-map-core`가 Web Mercator 카메라와 화면·좌표 변환을, `mappa-map-data`가 로컬 PMTiles·MVT 해독을, `mappa-map-render`가 도형 준비와 wgpu 렌더링을, `mappa-map-demo`가 macOS 창·입력·라벨·축척을 담당한다. 실행 중 타일 URL, 외부 지도 API, 지도 서버 호출 경로는 없다. 지리 좌표와 도로 형태는 임의로 만들지 않고 고정 원본에서 가져왔다. 색상·선 굵기·캐시 예산·줌별 표시 범위는 렌더링 설정이다.

현재 타일 형식은 PMTiles v3 내부의 gzip MVT다. MLT v1은 세 개 실제 타일로 크기와 해독 시간을 비교했으나 작은 타일의 해독이 더 느린 경우가 있어 실행 형식으로 바꾸지 않았다. 이 비교만으로 전체 지도에서 어느 형식이 우월하다고 결론 내리지 않는다.

세계 및 동아시아 원본은 고정 커밋 `ca96624a56bd078437bca8184e78163e5039ad19`의 Natural Earth 벡터다. 한국 도로·지형은 2026-09-22자 Geofabrik South Korea OSM 추출물과 별도 날짜가 고정된 OSM land polygons에서 빌드했다. 다운로드와 GDAL 추출은 **빌드 시 데이터 준비**이며, 앱 실행에 네트워크가 필요하지 않다. Natural Earth는 public domain이고, OSM 파생 PMTiles는 ODbL 1.0 및 화면의 `© OpenStreetMap contributors` 표기를 따른다. 재생성 명령과 원본 해시는 [MAP_DATA.md](MAP_DATA.md), [OSM_EXTRACT.md](OSM_EXTRACT.md)에 있다.

“자체 지도”의 범위를 구분해야 한다. 투영·타일 생성·캐시·렌더링·스타일 코드는 Mappa가 작성했지만, 지형·도로·지명 원본 데이터의 제작자는 각각 Natural Earth와 OSM이다. Natural Earth의 `1:10m`은 **1:1,000만 축척**으로, 10미터 위치 해상도를 뜻하지 않는다. OSM을 데이터 원본에서도 제외하려면 독립적으로 확보한 도로·수면·녹지·지명 데이터를 같은 타일 형식으로 다시 만들어야 한다. 대체 원본의 정확도와 오프라인 재배포 권한을 확인하기 전에는 현재 OSM 타일을 제거하면 한국 확대 화면의 도로·역·기관 정보가 사라진다.

## 3. 실제 표시 범위

| 카메라 범위 | 실제 타일 | 지역과 주요 레이어 | 파일 크기 | 이번 전수 감사 |
|---|---|---|---:|---:|
| z0–z4 | Natural Earth 1:110m | 세계 육지·수면·국경; 나라 이름은 별도 소스 | 209,232 B | 266개 성공 |
| 동아시아 z5–z7 | Natural Earth 1:10m | 상세 해안선, z6부터 도로·도시 | 1,174,286 B | 589개 성공 |
| 한국 일부 z8–z9 | OSM | 해안·수면·녹지·간선도로·도시 | 9,972,650 B | 173개 성공 |
| 수도권 일부 z10–z12 | OSM | 위 레이어와 일반 도로·역·공공기관 | 19,912,318 B | 840개 성공 |

네 PMTiles 합계는 **31,268,486 B**다. 나라 이름 파일은 별도 838,726 B다. 네 파일의 SHA-256과 크기는 이번 점검에서 [MAP_DATA.md](MAP_DATA.md)의 기록과 일치했다. 전수 감사에서 경계 안의 빈 바다 타일은 `absent`로 별도 집계했고, **해독 실패는 네 파일 모두 0개**였다.

상세 파일의 영역을 화면 전체가 벗어나면 더 넓고 단순한 파일로 돌아간다. 따라서 같은 줌에서도 장소와 화면 크기에 따라 표시 상세도가 달라질 수 있다. z16까지 카메라 확대는 되지만 수도권에서는 z12 원본을 16배 확대한다. 화면에 `0.95 m/px`가 표시돼도 지리 데이터의 정확도가 0.95m라는 뜻은 아니다. z8–z9는 화면 혼잡을 줄이기 위해 일부 도로 등급과 연결로를 표시하지 않는다. 건물, 경로 탐색, 전국의 동일한 상세 도로망은 없다.

## 4. 화면과 조작의 현재 결과

- 화면 이동: 마우스 드래그. 확대·축소: 휠, 트랙패드 핀치, `+`/`-`; 포인터를 기준으로 카메라를 조정한다.
- 네 색상 시안: Arcade, Lagoon, Candy, Sunset. 현재 기본값은 눈부신 노란 바탕을 줄인 Arcade다. 다른 시안은 같은 데이터·카메라로 비교 가능하며 최종 디자인 선택은 아직 하지 않았다.
- 이름과 기호: 세계 저줌 나라 이름, 한국 도시·역·공공기관 이름을 소스 좌표에서 표시한다. 화면 충돌 선별 때문에 한 화면의 모든 개체 이름을 보여주지는 않는다.
- 축척: 오른쪽 아래에 화면 중심의 물리 픽셀당 지상 거리(`m/px`), 카메라 줌 `z`, 실제 거리에 비례하는 막대가 있다. 상록수 캡처에서 z11.4는 `23.0 m/px · 2 km`, z16은 `0.95 m/px · 100 m`로 확인했다. 모니터의 물리 DPI가 주어지지 않아 `1:N` 인쇄 축척은 표기하지 않는다.
- 도로 선: 이전 z16 캡처의 점선처럼 보이는 테두리는 선분별 독립 사각형, 얇은 테두리·흰 중심선, 픽셀 샘플링의 조합이었다. 인접 선분의 바깥 이음새와 가장자리 0.5px을 보정하고 중심선을 회청색으로 조정했다. 동일 좌표의 변경 후 캡처에서 선이 연속해 보인다. 원본 도로 좌표는 이 수정에서 바꾸지 않았다.

## 5. 로딩·렌더링 구조와 실측

화면에 필요한 로컬 타일은 별도 작업 스레드에서 읽고 해독·도형 준비를 한다. 화면 중심에 가까운 타일부터 요청하고, 완료된 GPU 타일 업로드는 프레임당 최대 1개다. 정지한 화면은 계속 다시 그리지 않으며, 이전 기록의 실제 창 유휴 9초 후 `ps` CPU 값은 0.0%였다. CPU 해독 데이터의 **추정 페이로드** 예산은 64 MiB, GPU 타일 버퍼 예산은 128 MiB다. 이것은 프로세스 전체 메모리 상한을 뜻하지 않는다.

아래는 **이번 도로 선 보정 후** `target/debug/mappa-map-demo --async-street-benchmark`를 Apple M4 Metal, 1200×720 오프스크린에서 각각 한 번 실행한 값이다. 첫 준비는 요청 타일이 정착할 때까지의 시간이다. 이동 측정은 24px씩 40프레임, 지도·라벨 렌더링과 GPU 완료 대기를 포함한다. 입력 장치 지연·창 표시 지연·iPhone 성능은 포함하지 않는다.

| 위치·줌 | 첫 타일 준비 | 이동 중앙값 | p95 | p99 | 화면 안 미해결 타일 | 실패 |
|---|---:|---:|---:|---:|---:|---:|
| 서울 z8.4 | 482.7ms | 4.85ms | 5.27ms | 34.55ms | 0/40 | 0 |
| 상록수 z11.4 | 145.4ms | 6.88ms | 7.45ms | 32.87ms | 0/40 | 0 |
| 상록수 z16 | 35.9ms | 4.51ms | 4.65ms | 26.36ms | 0/40 | 0 |

이전 z11.4 한 번 측정은 중앙값 6.2ms, p95 6.6ms였다. 짧은 실행의 p99와 실행 간 차이가 흔들리므로 도로 보정 비용이나 휴대전화 FPS를 이 표만으로 확정하지 않는다. 과거 z8–z10 정지 화면의 동기 로딩은 2–3초대였고, 작업 스레드 이동은 화면 스레드의 긴 정지를 피하기 위한 변경이다. 한 번의 첫 화면 지연 자체를 0으로 만든 것은 아니다. 상세 수치와 측정 범위는 [BENCHMARK_MAP_ASYNC.md](BENCHMARK_MAP_ASYNC.md), [BENCHMARK_ZOOM_LOD.md](BENCHMARK_ZOOM_LOD.md)에 있다.

## 6. 이번 검증과 남은 위험

이번에 `cargo test`로 네 지도 패키지의 **17개 단위 테스트**가 통과했다. 같은 네 패키지의 `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `git diff --check`도 통과했다. 테스트는 투영·줌·축척, 실제 타일 읽기, 잘못된 MVT 거부, 소스 지명, 도로 굴곡 이음새 등을 포함한다. 네 PMTiles의 1,868개 실제 타일을 별도 감사해 해독 오류 0개를 확인했다.

가장 큰 지도 품질 미확인 항목은 **현실 도로와의 위치·연결 정합성**이다. 사용자가 네이버 지도와 비교해 차이를 지적한 것은 시각 피드백으로 기록했다. 동일 기준점의 실제 좌표 오차, 도로 누락률, 교차로 연결률을 측정하지 않았으므로 “상용 지도만큼 정확하다”는 판정은 내릴 수 없다. 현재의 OSM 추출 날짜, 표시 도로 등급 선택, 지역 경계, z12 상세 한도가 차이의 후보이며 각각 분리해 확인해야 한다.

그 밖에 전국 동일 상세도, z13–z16 신규 도로·건물 데이터, 실제 창의 연속 입력 p95/p99, 장시간 이동 시 프로세스 최대 메모리, iPhone GPU·배터리·메모리 측정은 남아 있다. Mappa 게시글·그래프 노드를 지도 위에 표시하는 기능도 아직 없다. 현재 Rust iOS UI에는 지도 패키지 의존성이 없으며 지도 화면 통합이 아직 없다. iPhone 13의 Developer Mode와 인증서는 준비됐지만 Personal Team 기기 등록 한도 때문에 설치 프로파일 생성이 실패한 상태다. 이 제약은 지도 코드 자체의 합격을 의미하지도, 지도 작업을 막지도 않는다.

Git 상태는 `HEAD=b6dda9f`이며 `origin=https://github.com/seoyd/mappa.git`가 설정돼 있다. 지도 패키지·데스크톱 데모·데이터·캡처는 현재 작업 트리에서 새 파일로 남아 있고, 기존 Cargo/README/문서에는 수정이 있다. **이번 지도 작업은 아직 커밋·푸시되지 않았다.** 따라서 GitHub에서 이 결과를 볼 수 있다고 보고하지 않는다.

## 7. 다음 작업의 우선순위

1. **도로 정합성 검증:** 상록수·서울의 고정 기준 좌표와 교차로를 선정해 원본 OSM 선, PMTiles 해독 선, 화면 선을 같은 좌표계에서 비교한다. 실제 데이터 누락, 타일 경계 손실, 렌더링 문제를 각각 집계한다.
2. **실제 상세 확대:** 우선 선정한 좁은 지역에 날짜·해시가 고정된 원본으로 z13–z16 타일을 만든다. 추가 도로 등급과 건물은 원본에 있는 것만 넣고, 파일 크기·타일 준비 시간·메모리·경계 연결을 다시 측정한다.
3. **시안 확정과 화면 검증:** 같은 좌표·줌의 비교 캡처로 색상, 글자 대비, 도로 등급별 굵기, 축척 가독성을 결정한다. 선택한 시안을 버전 관리한다.
4. **모바일 지도 통합:** Rust 지도를 iOS UI에 연결하고 Simulator에서 기능을 검증한다. 계정의 기기 등록 제한이 풀리면 실제 iPhone에서 FPS·메모리·발열·입력 지연을 측정한다.
5. **전달 상태 정리:** 지도 소스·필수 로컬 데이터·라이선스·재현 명령을 함께 커밋하고 GitHub 상태를 확인한다. 캡처·대형 빌드 중간 파일의 포함 여부를 구분한다.

이 순서는 현재 확인된 품질 격차와 검증 공백을 기준으로 제안한 것이며, 완료됐다는 뜻은 아니다.
