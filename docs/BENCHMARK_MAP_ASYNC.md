# 지도 화면 갱신 최적화 — 2026-09-24 KST

대상은 macOS Rust 지도 데모다. 화면에 필요한 로컬 PMTiles 조회·MVT 해독·도형 준비를 단일 작업 스레드로 옮겼다. 화면 스레드는 중앙에 가까운 타일을 먼저 요청하고, 프레임마다 완료 타일을 최대 1개 GPU에 올린다. 더 이상 쓰지 않는 압축 타일 사본은 CPU cache에서 제거했다. 라벨은 이름·종류·화면 배율별로 글꼴 조합 결과를 재사용한다. 타일 데이터·도형·레이어 순서·색·라벨 내용은 바꾸지 않았다.

같은 Mac mini Apple M4 / Metal, 1200×720에서 `--street-benchmark` 또는 `--async-street-benchmark`를 한 번씩 실행한 결과다. 두 측정 모두 지도·라벨 그리기와 GPU 완료 대기를 포함한다. 이동 구간은 상록수 주변 z11.4에서 24px씩 40프레임이다.

|---|---:|---:|---:|---:|---:|

별도 최종 실행에서는 상록수 z11.4가 첫 준비 149.9ms, 이동 중앙값 6.3ms / p95 7.7ms / p99 73.9ms였다. p99는 짧은 40프레임 측정에서 흔들렸으므로 개선이 확인됐다고 보지 않는다. 서울 z8.4의 최종 실행은 첫 준비 473.0ms, 이동 중앙값 5.4ms / p95 5.7ms / p99 24.0ms, 화면 안 빈 타일 0/40이었다. `--street-demo` 실제 macOS 창에서도 20개 타일이 로드되고 오류 없이 표시됐다.

품질 비교에서는 `--capture`와 `--async-capture`가 상록수 z11.4에서 PNG 바이트 단위로 같았다. 서울 z8.4도 동일했다. 최종 라벨 캐시 적용 후 상록수 z11.4 PNG 역시 이전 동기 캡처와 같았다. 테스트와 Clippy 검사에 통과했다.

이는 Mac의 오프스크린 및 창 실행 결과다. iOS 앱에는 지도가 아직 연결되지 않았으며, iPhone의 입력 지연·p95/p99·메모리 사용은 측정하지 못했다. 화면이 처음 비어 있다가 타일이 채워지는 시간은 대략 기존과 비슷하고, 로딩 중에도 화면 스레드가 타일 해독·도형 준비에 묶이지 않도록 바뀌었다.

## 후속: 도로 선 연결과 픽셀 경계

상록수 z16 동일 좌표 캡처에서 도로 테두리가 일정 간격으로 끊겨 보였다. 도로 원본을 변경하지 않고, 인접 선분의 바깥쪽 이음새를 삼각형으로 메우고 WGSL에서 선 가장자리 0.5px을 보정했다. 흰색 중심선도 배경과 구분되는 회청색으로 조정했다. 최종 캡처는 `artifacts/map-v0.3a/compare/sangnoksu-z16-road-connected.png`와 `sangnoksu-road-connected.png`다. z16은 z12 타일을 확대하므로 더 세밀한 도로 데이터가 생기지는 않는다.

이전 창은 정지한 뒤에도 88.3 FPS를 출력하며 반복 렌더링했다. 입력·창 변경·작업 스레드 타일 완료 때만 다시 그리도록 이벤트 루프를 바꿨다. 실제 창을 정지 상태로 9초 둔 뒤 `ps`가 보고한 CPU 사용률은 0.0%였다. 입력 제스처의 지연은 별도로 측정하지 않았다.

기본 Arcade 시안은 원본 OSM 도형을 유지하고 물을 더 깊은 파랑, 녹지를 분명한 초록, 도로 윤곽을 진한 청회색으로 조정했다. 작은 역·공공기관 라벨은 각각 16px·14px로 키웠다. 상록수 z11.4와 서울 z8.4의 채택 라벨 수는 이전과 같은 35개·23개이며 타일 해독 실패는 0개였다. 결과 이미지는 `artifacts/map-v0.3a/compare/sangnoksu-crisp.png`, `seoul-network-crisp.png`, `sangnoksu-z16-crisp.png`에 있다.

같은 Mac 오프스크린에서 새 시안과 이벤트 루프 코드를 빌드한 뒤 `--async-street-benchmark`를 실행했다. 상록수 z11.4 첫 타일 준비 146.2ms, 이동 중앙값 6.2ms / p95 6.6ms / p99 29.7ms였다. 서울 z8.4는 첫 타일 준비 467.6ms, 이동 중앙값 5.3ms / p95 5.7ms / p99 23.2ms였다. 두 이동 구간 모두 화면 안 빈 타일은 0/40프레임이었다. 이벤트 루프의 유휴 CPU 결과와 이동 벤치마크는 서로 다른 측정이다.
