# Mappa 지도 레이어와 실행 구조 — 2026-09-25

## 1. 무엇을 소유하고 무엇을 입력받는가

Mappa가 구현한 부분은 Rust 좌표·카메라, 원천 검증/변환, 타일 생성, 로컬 PMTiles 선택/해독, GPU 렌더링, 레이블·축척이다. 기본 세계 화면의 해안·국경·도시·주요 도로 좌표는 Natural Earth 원본에서 왔다. `canonical-proof`는 나주 공공 도로·SGIS 지명·ESA 토지피복을 MappaGeoDB로 정규화한 별도 지역 실증이다. 기본 세계 화면은 **아직 전 세계 MappaGeoDB가 아니다**. 두 경로 모두 화면을 그릴 때 외부 타일 API를 호출하지 않는다.

```mermaid
flowchart LR
    A[승인된 원천 파일] --> B{빌드 경로}
    B -->|기본 세계 화면| C[해시 확인 후 Rust 110m·10m 타일 빌더]
    B -->|나주 실증| D[권리·해시 manifest → Rust 어댑터 → MappaGeoDB]
    D --> E[지역 LOD·타일 빌더]
    C --> F[로컬 PMTiles / gzip MVT]
    E --> F
    B -->|승인된 지역 상세| J[원천 manifest 권리 게이트 → 지역 PMTiles 목록]
    J --> F
    F --> G[타일 선택·해독 → CPU 메쉬 → GPU 캐시]
    G --> H[wgpu / Metal 지형 레이어]
    H --> I[문자 레이블·축척 오버레이]
```

## 2. 화면 확대와 파일 선택

`mappa-map-core`의 `MapCamera`가 경위도를 Web Mercator의 단위 정사각형으로 변환한다. CPU 좌표는 f64이고 타일 키는 `(z,x,y)`다. 화면 밖 한 타일 여유를 포함해 보이는 키를 구한다. 날짜변경선을 넘는 가로 이동은 같은 타일 키를 반복 사용하고 화면 배치 좌표만 풀어서 유지한다. 극점은 표현하지 않으며 위도 약 ±85.05°에서 제한한다.

| 기본 세계 모드 | 파일 | 실제 데이터 | 선택 조건 |
|---|---|---|---|
| z0–z4 | `world_110m.pmtiles` | 1:110m 육지·호수·국경; 나라이름은 별도 원천 좌표 | 세계 축소 화면 |
| z5–z7 | `world_10m.pmtiles` | 1:10m 육지·호수·국경; z6부터 선별된 주요 도로·도시·하천 중심선 | 전 세계 Web Mercator 범위 |
| z8–z9 화면 확대 | 선택된 파일의 최고 z7 타일 | 기존 벡터를 확대 | 위치·객체 상세는 증가하지 않음 |
| z10–z15 | 승인된 지역 PMTiles | 뉴욕주·뉴저지주·델라웨어주·코네티컷주·로드아일랜드주·매사추세츠주·뉴햄프셔주·버몬트주·메인주·메릴랜드주·펜실베이니아주·웨스트버지니아주·오하이오주·버지니아주·워싱턴 DC 522개 카운티 상당 단위·프랑스 파리 D075·GB 52개 격자·캐나다 13개 지역 도로와 프랑스 파리·매사추세츠주·뉴햄프셔주·버몬트주·메인주·메릴랜드주·펜실베이니아주·웨스트버지니아주·오하이오주·버지니아주·워싱턴 DC·뉴욕시 5개 카운티 수면은 z10부터, 뉴욕시 주변 공원 경계는 z12부터, 파리 `FICTIF=Non` 여객역은 z13부터, 모나코·Queens 동부 건물은 z14부터 | 출처 manifest와 아카이브 표기·범위 일치 확인; 나머지 지역은 중립색 |
| z16 화면 확대 | 해당 지역 최고 z15 타일 | 기존 지역 벡터를 확대 | 위치·객체 상세는 증가하지 않음 |

`MAPPA_DATASET=canonical-proof`에서는 위 세계 파일을 열지 않고 나주 `artifacts/map-v0.3c/naju-roads.pmtiles`만 연다. 이 파일은 z10–z15 자료이고 이후 확대는 z15 오버줌이다. `legacy-osm`과 `public-naju`는 과거 비교 모드이며 기본 세계 모드가 아니다. 화면의 `m/px`는 카메라 중심 위도와 현재 화면 배율에서 계산한 **표시 축척**이다. 지리 위치 오차나 원본 해상도를 뜻하지 않는다.

기존 `east_asia_10m.pmtiles`는 비교용 파일로 남지만 기본 세계 모드가 열지 않는다. 세계 10m 아카이브가 동아시아에도 적용된다. [기존 지역 목록](../assets/map/regional_packs.toml)·[GB 도로 목록](../assets/map/gb_regional_packs.toml)·[캐나다 도로 목록](../assets/map/ca_regional_packs.toml)의 파일은 시작할 때 canonical manifest의 권리 게이트를 통과해야 한다. 렌더러와 배포 도구는 `assets/map/`의 `regional_packs.toml` 및 `*_regional_packs.toml`을 이름순으로 찾아 새 국가 카탈로그도 읽는다. manifest 범위로 만든 z5 셀 인덱스에서 후보를 고르고, PMTiles는 필요한 지역의 첫 타일 요청 때 열어 헤더와 출처를 확인한다. 열린 파일은 최근 사용 순서로 최대 16개를 유지한다. 현재 목록은 기존 69개·GB 52개·캐나다 15개, 총 **136개 파일**이다. 122개를 별도 디렉터리에 복원한 뒤 전부 열어 z14 타일을 읽는 테스트가 통과했고, 이후 추가한 조지아주 다섯 팩을 포함한 127개 카탈로그 로드 테스트도 통과했다. 앨라배마주 세 팩과 미시시피주 세 팩과 루이지애나주 세 팩은 실제 화면 검증을 통과했다. GB 네 지역·캐나다 13개 지역과 미국 22개 주·DC의 여러 Metal 캡처가 있지만, iPhone 성능·공개 릴리스에서 설치 검증은 아직 없다.

## 3. 타일 안의 데이터 레이어와 그리는 순서

MVT 지오메트리를 `DecodedTile`의 typed 레이어로 해독한다. `mappa-map-render::prepare`가 다각형은 lyon 삼각형으로, 선은 폭을 가진 사각형/이음부 메쉬로 만든다. 표식은 별도 메쉬, 글자는 glyphon을 사용한다. 화면 순서는 다음과 같다.

| 순서 | 레이어 | 지도에서의 역할 | 기본 세계 모드 | 나주 canonical 실증 |
|---:|---|---|---|---|
| 배경 | ocean clear color | 바다·빈 바탕 | 바다 | 미기록 영역을 회색으로 표시 |
| 1 | `land` | 육지 면 | 개략 지도에 있음; 지역 상세에는 없음 | 없음 |
| 2 | `green` | 녹색 면 | 뉴욕시 주변 Census 2025 공원 경계; 실제 수목 피복은 아님 | ESA 2021 수목 피복; 법정 공원이 아님 |
| 3 | `water` | 호수·수면 면 | Natural Earth 호수; 뉴욕시 지역은 Census 2025 수면 폴리곤 | ESA 2021 영구수면 분류 |
| 4 | `waterway` | 강·하천·호수 중심선 | z6에서 원본 등급 0–5, z7에서 0–7 | 없음 |
| 5 | `coast` | 육지 외곽선에서 만든 해안선 | 있음 | 없음 |
| 6 | `boundary` | 육상 국가 경계 | 있음 | 없음 |
| 7 | `road_surface` | 도로 면 | 없음 | 나주 공식 도로면 |
| 8 | `road`, `road_local`, `road_collector`, `road_major` | 도로 선; 외곽선과 안쪽 색을 두 번 그림 | 개략에는 선별된 `road`; 뉴욕주·뉴저지주·델라웨어주·코네티컷주·GB·캐나다 13개 지역 상세에는 등급별 도로 | 폭 기준 3등급 도로 중심선 |
| 9 | `building` | 건물 다각형 | 모나코 상세에만 있음 | 없음 |
| 10 | `place`, `station`, `civic` | 도시/지명·역·기관 표식 | 개략에는 선별된 도시; 지역 상세에는 없음 | SGIS 읍면동 이름만; 역·기관 없음 |
| 11 | glyphon 문자, 축척 | 이름·출처·m/px·거리 막대 | 나라/도시 이름·한계 문구 | 읍면동 이름·출처 표시 |

표는 **렌더러가 지원하는 레이어**와 **실제 원천에 데이터가 있는 레이어**를 구분한다. 예를 들어 역·기관 메쉬는 구현돼 있지만 기본 세계 파일과 나주 canonical 파일에는 해당 객체가 없다. 건물은 모나코 실증에서 생성·표시되며, 철도는 실제 데이터·렌더 경로가 없다. 근거 없는 위치는 채우지 않는다.

## 4. 로컬 실행·성능 경계

`mappa-map-data`는 PMTiles v3 파일을 메모리 매핑해 gzip MVT를 읽는다. 압축 해제된 타일은 최대 4 MiB, 레이어는 최대 5만 피처로 제한하고 타입·좌표를 검사한다. 실시간 로더는 작업 스레드 하나, 대기 요청 최대 12개, 프레임당 GPU 업로드 최대 1개를 사용한다. 화면 중심에 가까운 타일을 우선하고 더 이상 필요한 영역이 아닌 대기 요청은 건너뛴다. 디코드 타일 CPU 추정 예산은 64 MiB, GPU 메쉬 예산은 128 MiB이며 오래 사용하지 않은 타일부터 제거한다. 이 숫자는 메쉬/디코드 캐시 예산이지 앱 전체 메모리 한도가 아니다.

스타일은 같은 형상에 색·선 폭만 바꾸는 4개 팔레트(Arcade, Lagoon, Candy, Sunset)다. 문자는 원천의 이름/우선순위를 읽고 화면 사각형 충돌을 피하며, 축척은 현재 카메라에서 계산한다. 스타일 변경은 좌표나 원천을 바꾸지 않는다. Mac Metal 캡처와 1회 이상 테스트는 있지만 iPhone GPU/메모리 결과는 없다.

## 5. 실제 범위 감사와 다음 경계

`audit_world_tile_presence`는 세계 10m 파일의 z7 타일을 읽어 z3의 8×8 구역별 **레이어 존재 타일 수**를 CSV로 기록한다. [현재 결과](../artifacts/world-10m/tile-presence-z7-by-z3.csv)는 전체 64구역 중 육지 타일이 있는 곳 61, 수계선 타일이 있는 곳 29, 도로선 타일이 있는 곳 25, 육지는 있으나 도로선 타일이 없는 곳 36이다. z7 타일은 8,017개 해독, 8,367개는 비어 있다. 이 집계는 각 넓은 구역에 **자료가 한 번이라도 나타났는지**만 뜻한다. 국가별 도로·수계 완성도나 위치 정확도·통행 가능성을 측정하지 않는다.

다음 상세 구축 단위는 `원천 권리·버전/해시 → 좌표계와 형상 검증 → MappaGeoDB provenance → 지역 타일 → 도로 연결성과 독립 위치 기준점 → 화면/기기 측정`이다. 나주 지역도 건물·철도·법정 공원 경계·독립 정확도 자료가 없어 S16 판정은 [`NO_GO_SOURCE_COVERAGE`](MAP_V0_3C_GATE_AUDIT.md)다. 전 세계 거리 지도로 완료 판정하지 않는다.

```bash
cargo run --offline -p mappa-map-data --bin audit_world_tile_presence -- \
  assets/map/world_10m.pmtiles 3 artifacts/world-10m/tile-presence-z7-by-z3.csv
```
